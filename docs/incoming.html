Incoming requirement candidates

How to use this document. Each block below is a candidate requirement derived from a raw record, ranked against the specification for congruency and complexity. Read the blocks and discuss them. The page is static, so the file is edited in a text editor and committed like any document; the browser is for reading and for copying a block. When you decide a candidate is worth acting on, select the block, copy it, and paste it into an intake session. Nothing else reads this file, and nothing in it changes the specification until a decision is accepted.

Legend

Color marks congruency only, and the class name is always printed in the block. Complexity is the size badge. An easy patch is clarifies or amends at S. A hard change is amends or contradicts at L or XL.

  • already satisfied (gray): the specification already requires it.
  • clarifies (green): it sharpens an item without changing it.
  • amends (amber): it changes an existing item.
  • contradicts (red): it conflicts with an existing item.
  • brand new (blue): the specification is silent.
  • nonsense (muted, struck through): it cannot be acted on.

Kind is bug, amendment, feature or question. Complexity is S, M, L or XL, from the items touched, the files likely in scope, external provider effects and data migrations.

Deferred until after the first release: 2026-09-19, owner design session: strategies that score without forecasting

Written against the specification of 2026-09-19. Since then the launch profile has disabled performance-based selection and mutation and replaced the use and attention tracks with three citation targets. The rankings and the cited items below have not been re-read against the current specification.

Three ways a population can look as if it learned while it did not: a genome that echoes the card's head probability and scores like the regression baseline; a claim type with no baseline of its own, won by the cheapest claims of it; and a population fitted to one season's topics whose loss when the field moves reads as the genomes getting worse. Each candidate here makes one of them measurable, or takes away its payoff, without adding a model or a layer.

Candidate C-2026-09-19-251

Statement: The scorer MUST measure, for each genome and cycle, the agreement between the genome's confidences and the head probabilities on the same questions, and record a flag when it exceeds a threshold written down beforehand.

Kind: amendment

Congruency: amends

Complexity: S

Spec items: SDD-IN-05, SDD-IN-06, SDD-RD-08, SDD-SR-18, SDD-FT-16

Rationale: SDD-IN-05 catches confidences that cluster at one value. A genome that reports the card's head probability with a small nudge passes that test, spreads its confidences as the heads do, and scores like the regression baseline while forecasting nothing. One agreement value per genome per cycle, computed from sealed claims and the cards in the sheet's snapshot, no model. The threshold is a record under SDD-SR-18. Leakage check: none; it reads what the card showed at the snapshot.

Candidate C-2026-09-19-254

Kind: amendment

Congruency: amends

Complexity: S

Spec items: SDD-AG-16, SDD-FT-15, SDD-AG-20, SDD-SR-18
