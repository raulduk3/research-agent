# Jev live rubric run over release 1b papers

Dated 2026-09-23. The first live run of the launch rubric (`jev-rubric-v1`,
eight `choice` questions, #60) against the provider, over real papers from
the release 1b export, through #60's own input builder and answer decoder.
It records what the provider does on real inputs; it is not the RD-22
smoke test, whose pass criteria and owner review are #61's and #62's.

## Setup

- Model pinned to the immutable revision `jev-1.13.0`; every response
  carried it back as `model`.
- 60 papers drawn with seed 20260923 from the 3,403 exported paper texts;
  assessed text built by `assessments/input.py#build_assessment_input`
  from each paper's extraction (body, appendix, caption and table blocks in
  document order); answers decoded by
  `assessments/schemas.py#parse_field_answers`.
- Two requests in flight, 90 s timeout, spend guard at 40M input tokens.
- Raw records: `/Volumes/research-agent/jev-smoke/2026-09-23.jsonl` (one
  line per paper: status, sizes, latency, usage, the eight answers).

## What the run established

- **Wire shape.** Each field answer is `{"type": "choice", "choice",
  "confidence", "probabilities"}`; the response carries `usage` with
  `input_tokens` and `output_tokens`. The decoder as first written required
  the exact key set without `type` and would have refused every real
  response; fixed the same day.
- **Rounding.** The provider rounds each probability to two decimals, so a
  distribution over up to eight categories can sum to 0.99 or 1.01. The
  decoder's 1e-6 tolerance refused six of sixty papers for it. The
  tolerance is now 0.05; values are recorded as sent and never renormalized.
  A second request for the same paper returned a distribution summing to
  exactly one, so answers are not deterministic across calls.
- **Token accounting.** Against the gateway's own `usage`, English prose
  costs 4.5 characters per token plus about 314 tokens of question
  overhead (`input_tokens = 314 + chars / 4.5` fit three sized probes
  exactly); real papers cost 2.95 characters per token. The launch counter
  (`assessments/tokens.py`) charges 2.5, above every observed input.
- **Size.** A quarter of real papers do not fit one request. RD-17 forbids
  silent truncation and the worker refuses them; what to do instead is
  decision #262.

## What it does not establish

- Not accuracy: nothing here is compared with a human label. That is #61's
  qualification against annotated papers, with rubric examples drawn from
  the development set, which these runs did not have.
- Not the smoke test (RD-22), the preregistration (RD-23) or the readiness
  record (RD-24).
- Not retention terms; the provider still publishes none.

## Rubric v2 live check (same day)

`jev-rubric-v2` sent to `jev-1.13.0` over 48 papers drawn from the same
export (`/Volumes/research-agent/jev-smoke/2026-09-23-v2.jsonl`):

| Outcome | Papers |
| --- | --- |
| decoded, all eight fields | 18 |
| refused before the call, `input_too_large` | 10 |
| decode refused, first run only (see below) | 20 |

The 20 refusals were one defect: the live `score` answer is the
probability-weighted position on the scale (`1.67` on the 0-4
`evaluation_rigor` scale), not an integer point, and the first decoder
required an integer. After the fix (`score` a number from 0 to n-1, the
most probable point derived from the distribution) every in-size paper
of the second run decoded, 18 of 18. Both runs together cost about
USD 0.02.

Field summaries over the 18 decoded papers, for a first sense of the
scales (not a qualification):

| Field | Primitive | Summary |
| --- | --- | --- |
| `primary_contribution` | choice | method_system 9, theoretical_result 4, empirical_analysis_replication 4, dataset_resource 1 |
| `evaluation_rigor` | score 0-4 | mean 2.42, range 0.01 to 3.94 |
| `limitations_candor` | score 0-3 | mean 2.08, range 0.78 to 2.95 |
| `novelty_as_claimed` | score 0-3 | mean 0.89, range 0.05 to 1.70 |
| `claims_supported_by_evidence` | noul | mean 0.68, range 0.37 to 0.84 |

`novelty_as_claimed` sits low and narrow; `reproducible_from_materials`
is low, as expected for text without an artifact check. Neither is a
defect, but both are worth watching in the RD-22 smoke before activation.
