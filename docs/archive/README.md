# Historical documentation

These records describe the earlier forecasting, qualification, rating and distributed-service platform. They are retained for provenance and maintenance of historical code. They do not define the capped swarm release or its launch prerequisites.

- `implementation/` contains dated storage, corpus, qualification, Linux-boundary and historical front-end records.
- [Launch population](launch-population.md) describes the earlier fixture retained at `docs/launch/seeds.json`.
- Earlier accepted decisions remain in `docs/decisions/` so the amendment ledger keeps its provenance.
- `docs/contracts/api-v1/` contains schemas used by the historical `front-end/`. The active swarm API is documented in `deploy/beta/README.md` and `apps/swarm-web/API.md`.
- `docs/evidence/` retains dated observations and permission records. They establish only the activity and period they describe.

The root SDD and TDD define current scope. An old reference to a retired requirement does not restore that requirement. Retained JSON fixtures keep their original paths because historical commands and tests consume them.
