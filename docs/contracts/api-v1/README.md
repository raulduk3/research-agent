# JSON contract v1 (`/api/v1`)

Every HTML route of the four web apps (rating, inspector, weekly report, owner actions) has a JSON twin under `/api/v1/`, served by the same app from the same view it renders (`src/research_agent/web/api.py`, #249). `endpoints.json` is the endpoint table: app, method, path, the HTML route it twins, the success status and the schema its `data` validates against. The schemas in this directory are the copy the repository owns; `tests/contracts/test_api_v1.py` checks them and the table against the apps' routes, and `tests/web/test_api_v1_*.py` validate a real response of every endpoint against them.

## Rules

- **Envelope.** Success is `{"contract": "1", "data": {...}}` (`envelope.json`). A refusal is `{"contract": "1", "error": {"code", "message", "field"}}` (`error.json`): `code` is fixed by the status (400 and 422 `invalid_request`, 401 `unauthenticated`, 403 `forbidden`, 404 `not_found`, 409 `state_conflict`, 502 `not_saved`, 503 `unavailable`), `message` is the reason, and `field` names the request field or header at fault, or is null. An owner command's refusal reason (`invalid_edit`, `population_floor` and the rest) is its `message`.
- **Lists.** Every array directly under `data` is `{"items": [...], "next_cursor": string | null}`. A non-null `next_cursor` is passed back unchanged as the list's cursor query parameter (`cursor`, or `forecast_cursor` for an agent's verdicts). Arrays inside a record (a run's `allowed_tools`, a report's `rows`) stay arrays.
- **Instants and money.** Every instant is the repository's one UTC format, `YYYY-MM-DDTHH:MM:SS.ffffffZ`. Money is integer micros (`budgets.spend_micros`).
- **Gated and absent fields.** A field a view withholds is omitted, never sent as null: a rater's digest entry is closed to `paper_hash`, `digest_entry_id`, `title` and `abstract` (SR-21, SR-22, SR-25), an unrated entry of the owner's digest carries only `entry_id`, `paper_hash`, `display_position` and `rated: false`, and the owner's agent view has no `inspected` field when the app has no inspector client. A null means the record says none (`genome` with no population record, `admission` with no owner action).
- **POST.** Every POST with a session carries `X-CSRF-Token` (the session's token, returned by `POST /api/v1/login` and on every view that renders a form) and `Idempotency-Key` (1 to 255 characters, chosen by the client per intended action). A missing or wrong token is 403, a missing key 400. The same key with the same request returns the first answer again, marked `X-Replayed: true`, and changes nothing; the same key with a different request is 409. Keys are scoped to the session's principal. A rating's key is also passed to storage, so a retry is replayed there even after the app restarts. `POST /api/v1/login` is the one POST without a session and carries neither header, exactly as the HTML sign-in form carries no CSRF token.
- **Bodies.** A POST body is a closed JSON object of string fields; an unknown, missing or non-string field is 422 naming it. The rating body is `{digest_entry_id, paper_hash, value}`; an edit is `{lineage_id}` plus any of the four policy parts; a seed is `{island, lineage_id, template_configuration_id}` plus all four policy parts; retire and logout take `{}` or no body.
- **Stability.** A v1 field is never renamed or removed and its meaning never changes. Adding a field is allowed and goes into its schema in the same change. Anything else is `/api/v2`.
